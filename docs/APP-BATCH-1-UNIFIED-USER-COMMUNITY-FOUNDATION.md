# APP第一批：统一用户、社区互动与后台管理底座

本文件是 TRRB iOS / Android App 第一批开发的固定验收规范。网站轮次与 APP 批次完全分离；本批固定 10 个节点的名称、顺序和验收标准不得在执行过程中随意改变。

## 总原则

- iOS、Android、trrb.net 与 trrb.net/admin 共用同一用户身份和互动数据源。
- 不建立独立 App 后台；社区管理统一进入现有 `/admin/`。
- 游客可以浏览公开新闻和法律资料；需要写入个人/社区数据的能力必须经过身份认证与授权。
- 不得把 service-role/admin secret 暴露到网站公开前端或移动客户端。
- 不得通过降低 RLS、安全、审核、删除或数据一致性标准制造 PASS。
- 不得影响网站现有新闻排序、法律数据库事实约束或第十七轮法律任务。
- 每个节点必须有代码/数据库证据和自动或可复验的验收证据；“已写代码”不等于 PASS。
- 节点 10 必须重新验证节点 1—9；只有最终日志明确输出 `APP BATCH 1: 10/10 PASS` 才能宣布第一批完成。

## 固定10个节点

### 1 TRRB统一用户数据库与身份架构

验收：
- Supabase Auth 为唯一认证身份源。
- `profiles` 以 auth user id 为主键/外键。
- 评论、收藏、历史、通知偏好、屏蔽、举报等全部引用统一 user id。
- 核心用户表启用 RLS，并有最小权限策略。
- migration 可重复审计，不能依赖客户端自行创建 profile。

### 2 随机昵称与默认头像生成机制

验收：
- 新注册用户由可信数据库/服务端自动获得默认昵称与头像。
- 默认昵称有足够组合空间、冲突重试和唯一性约束。
- 默认头像使用 TRRB 自有/可合法分发资产，不依赖不受控第三方头像服务。
- 用户可以修改昵称/头像，并记录 custom 状态。
- 管理员、官方、TRRB/唐人日报等保留身份不能被普通用户冒充。

### 3 iOS/Android统一注册、登录与会话管理

验收：
- iOS 与 Android 使用同一 Auth 项目。
- 游客浏览不强制注册。
- 注册、登录、退出、会话恢复、失效会话均有明确 UI 状态。
- 支持第一版确定的认证方式，并满足 Apple/Google 平台要求。
- 客户端不保存管理员密钥。

### 4 用户个人资料与账号设置

验收：
- “我的”页面能读取真实登录状态和 profile。
- 用户可修改允许修改的昵称、头像及公开资料。
- 修改结果在网站/App共用数据中一致。
- 对非法昵称、保留词、超长字段和异常上传有服务端约束。

### 5 新闻评论、回复与楼层关系

验收：
- 已登录用户可对有效已发布文章评论。
- 支持回复关系，不能形成无效 parent/article 关系。
- 评论列表稳定分页、按明确规则排序。
- 删除/隐藏状态不会向普通用户泄露正文。
- App 与未来网页评论使用同一数据表/API。

### 6 评论点赞、举报、审核与社区治理

验收：
- 每用户每评论最多一个点赞记录。
- 用户可以举报，不能通过客户端伪造其他用户身份。
- 支持 published/pending/hidden/deleted 等治理状态。
- 有频率限制/滥用防护方案。
- 管理操作有可审计记录；封禁后写入能力受控。

### 7 收藏与阅读历史云端同步

验收：
- 游客继续支持设备本地收藏/历史。
- 登录后可把本地数据安全合并到云端，不制造重复记录。
- 同账号跨 iOS/Android 可读取云端收藏。
- 用户只能读写自己的收藏和历史。
- 清除历史与取消收藏能正确同步。

### 8 统一后台“用户与社区”管理中心

验收：
- 功能进入现有 `trrb.net/admin/`，不建立第二套后台。
- 至少包含用户管理、评论审核、举报中心、账号状态/封禁管理入口。
- owner/admin/moderator/editor 权限边界明确，普通编辑不得自动获得最高用户管理权限。
- 后台关键写操作经过服务端授权并记录审计。

### 9 账户注销、数据删除与隐私闭环

验收：
- App 内存在明确的账户删除入口，不以“停用账户”代替删除。
- 网站提供 App 外可访问的账户删除说明/申请入口。
- 删除请求由可信服务端执行 Auth 用户删除和关联个人数据清理。
- 删除结果可验证；确需依法/安全保留的数据必须最小化并有保留理由。
- App Store / Google Play 所需删除路径和隐私说明可复验。

### 10 APP第一批生产总验收

验收：
- 在当前 main/生产配置上重新验证节点 1—9。
- iOS、Android、网站 API、Supabase 与 `/admin/` 完成联调。
- 不存在已知严重越权、跨用户数据泄露、评论身份伪造、注销失败或管理员密钥暴露。
- 自动验收日志逐项输出节点 1—10 PASS。
- 最后一行必须精确输出：`APP BATCH 1: 10/10 PASS`。
