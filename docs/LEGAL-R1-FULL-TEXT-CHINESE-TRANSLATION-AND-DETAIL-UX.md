# LEGAL-R1：官方法律全文中文化、折叠阅读与全链路完整性

状态：ACTIVE

本轮固定10个节点，名称与顺序不得更改：

1. 官方法律正文可获取性、来源版本与 recordId 全量盘点
2. 官方 PDF/HTML 正文提取与原文结构完整性治理
3. 官方正文逐段一比一中文全文翻译流水线
4. 中英文段落映射、完整率与法律含义忠实度审计
5. 法律详情页中文全文默认折叠与一键完整展开
6. 统一法律数据库中文全文 100% 覆盖与零占位治理
7. 官方来源更新触发、译文失效重建与版本审计链
8. 搜索、筛选、关联发现与错误降级兼容全文中文层
9. 法律 SEO、Sitemap、内链及首页4天新闻规则回归
10. LEGAL-R1 最终生产总验收

## 总原则

- 本轮建立在第十七轮严格统一版之上；第十七轮所有事实约束、官方来源限定、搜索规则、去重规则、生产证据要求和首页4天新闻规则继续生效，不得降低。
- 第一方事实源继续限定为 SCOTUS、13个联邦巡回上诉法院、DOJ/EOIR BIA precedent decisions、White House Executive Orders、Federal Register API。
- BIA仅表示公开先例/precedent decisions，不得表述为“BIA全部裁决”。
- 不复制 Westlaw、Lexis 或其他商业法律数据库的编辑摘要、headnote或商业标注。
- 官方原文是事实主层；中文全文是辅助理解层，不替代官方文本。
- 不得让 AI 猜测、补写或扩展官方原文不存在的事实、理由、裁判结论、法律效果或预测。
- 每个节点必须同时具备代码级验收、数据级验收和生产证据才可 PASS。
- 节点 PASS 严格串行；开发实现可以并行。
- 只有节点10重新验证节点1—9并明确输出 `LEGAL-R1: 10/10 PASS` 才能关闭本轮。

## 全文中文化硬标准

- 对“可获取官方 PDF 或官方 HTML 正文”的正式法律记录，必须提供与官方原文结构对应的完整中文全文，不允许使用摘要、要旨、概述或省略性翻译冒充全文。
- 标题、章节标题、正文段落、核心规则、裁判结论、命令/规则条款必须保持可追溯对应；允许中文语序调整，但不得改变法律含义。
- 每条全文译文必须与正式法律记录通过 `recordId` 一一绑定，并同时绑定 `datasetVersion`、官方 URL、原文版本/抓取版本与生成时间。
- 原文更新后，旧译文不得继续被标记为当前版本；必须进入失效、重建和重新验收流程。
- 无法获取官方正文的记录不得伪造全文。必须明确区分 `fullTextAvailable=false` 与“翻译缺失”。
- 官方正文可获取但全文译文缺少任意段落、章节或必需元数据，均为 FAIL。
- 正式生产页面不得以“中文解析正在生成”“中文信息整理尚未生成”等占位状态代替已要求存在的中文全文。

## 统一覆盖硬标准

继续继承第十七轮：

- `totalAnalyses === totalLegalRecords`。
- `coveragePct === 100`。
- `completeCoveragePct === 100`。
- orphan analyses = 0。
- duplicate record IDs = 0。
- metadata mismatch = 0。
- dataset version mismatch = 0。
- required fields missing = 0。
- bad disclaimer = 0；commercial leak = 0；BIA overclaim = 0。

本轮新增：

- `fullTextEligibleCount` 必须动态取自当前统一数据库中可获取官方正文的记录数，不允许固定旧分母。
- `fullTextTranslatedCount === fullTextEligibleCount`。
- `fullTextCoveragePct === 100`。
- source paragraph/section orphan = 0；translation paragraph/section orphan = 0；duplicate segment binding = 0；source-version mismatch = 0。
- 不得通过把实际可获取正文的记录错误标记为 `fullTextAvailable=false` 来降低分母。

## 节点1验收标准

节点1“官方法律正文可获取性、来源版本与 recordId 全量盘点”必须满足：

- 从当前 `data/legal/unified-legal-authorities-latest.json` 动态读取总量，不使用固定历史数字。
- 每条记录必须有唯一 `id/recordId`、`sourceSystem`、`officialUrl` 或可验证的第一方来源标识。
- 对存在 `officialPdfUrl` 或明确官方正文 URL 的记录，建立全文可获取性清单；PDF 与 HTML 必须区分。
- 盘点结果必须绑定当前 `datasetVersion`，数据库版本改变时旧盘点自动失效。
- 不允许重复 recordId、空 recordId、孤立来源或跨版本清单继续 PASS。
- 自动化审计必须输出总记录数、各来源数量、全文候选数、PDF候选数、HTML候选数和错误数量。

## 节点2验收标准

- 提取结果必须保留官方原文标题、章节/段落顺序与可审计源定位。
- 对 PDF 优先使用文本层；只有确无文本层且确有业务必要时才进入 OCR，并单独标记 OCR 来源与质量状态。
- 页面页眉页脚、重复导航、下载按钮等非正文噪声不得冒充正文段落。
- 正文提取失败不得被空字符串、摘要或元数据填充伪装为成功。

## 节点3验收标准

- 翻译输入必须来自节点2已验收的官方正文结构，不得从新闻摘要、第三方页面或既有短摘要反推全文。
- 每个源段落/章节拥有稳定 segmentId，并与唯一中文 segment 一一映射。
- 不得省略不方便翻译的段落；无法可靠翻译时必须显式失败并阻止该记录进入完整状态。

## 节点4验收标准

- source segment count 与 translated segment count 对所有全文候选逐条一致。
- 顺序、父子章节关系、recordId、datasetVersion/sourceVersion 必须一致。
- 自动审计必须能检测遗漏、重复、错绑、跨版本与明显摘要化替代。

## 节点5验收标准

- 法律详情页的“中文全文”默认折叠，不在初始页面一次性铺开全部译文。
- 用户点击后完整展开，再次点击可收起；不得只展示前若干段或截断文本。
- 折叠状态不改变底层全文数据完整性；官方原文入口持续可见。
- 键盘、屏幕阅读器、移动端均可操作；使用语义化 `button`、`aria-expanded`、`aria-controls` 或等价可访问实现。

## 节点6验收标准

- 第十七轮全部100%中文结构化覆盖指标继续严格满足。
- 对所有当前全文候选同时满足全文中文覆盖100%。
- 正式详情页不存在用摘要冒充“完整中文全文”的记录。
- 新增官方记录后分母立即变化；未完成完整译文前节点6自动重新 FAIL。

## 节点7验收标准

- 官方正文或统一数据库版本变化后，相关译文自动标记过期并进入重建。
- 保留 recordId、旧/新 sourceVersion、旧/新 datasetVersion、更新时间和审计状态。
- 不覆盖删除历史证据来制造版本一致。

## 节点8验收标准

- 中文全文可参与法律站内检索，但精确标题/案号/引证/官方字段高权重规则不得回退。
- q/source/body/type/page 分享URL、13巡回法院筛选、相关判例发现继续稳定。
- 全文层暂时不可用时不得影响官方事实层展示，也不得显示虚构占位内容。

## 节点9验收标准

- 法律详情 canonical、Sitemap、结构化数据和内部链接继续完整。
- 中文全文折叠不得通过隐藏/截断方式造成错误 canonical 或正文路由。
- 首页新闻仍只走统一实时已发布入口，超过4天一律不显示，不得用历史静态归档补位，按真实发布时间倒序。

## 节点10最终验收标准

- 必须以当前 main、当前统一法律数据库版本和当前生产部署重新执行节点1—9，不得引用旧 PASS。
- 必须确认结构化中文覆盖100%与全文候选中文全文覆盖100%。
- 必须确认详情页中文全文默认折叠且可完整展开。
- 必须确认不存在摘要冒充全文、跨版本译文、错绑/孤儿段落、占位状态或首页超过4天旧闻回归。
- 只有全部满足后允许输出：`LEGAL-R1: 10/10 PASS`。
