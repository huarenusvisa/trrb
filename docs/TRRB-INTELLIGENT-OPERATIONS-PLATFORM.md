# 唐人日报智能内容平台治理规范

状态：第一版（整合基线）

## 1. 总体结构

平台只保留两个顶层机器人，职责严格分离：

1. **TRRB迁移收口机器人（独立）**
   - 只读检查旧 WordPress 数据、Supabase 迁移、旧 URL、图片附件、旧代码残留和重复程序。
   - 不发布内容、不修改数据库、不修改首页、不部署。
   - 发现问题只报告证据、影响范围和建议，不与运营流程争夺写权限。

2. **唐人日报智能运营总机器人**
   - 统一调度下列九个业务中心。
   - 所有代码改动必须使用独立分支和草稿 PR。
   - 第一阶段不直接合并、不直接部署、不删除数据。
   - 已暂停的旧机器人不得自行恢复。

## 2. 唯一数据与执行原则

- **单一事实源**：正式内容、状态、分类、推荐标记由 Supabase 的正式表和已确认视图提供；不得另建第二套平行内容库。
- **单一写入者**：同一轮运行最多允许一个业务中心修改共享区域，包括首页、内容状态、路由、Sitemap、公共 API 和部署配置。
- **先读后写**：每次运行先读取最新 main、打开的 PR、CI 和生产状态；发现其他写入任务时停止共享区域改动。
- **可回滚**：代码变更只进入独立分支和草稿 PR；数据库结构变更必须有迁移脚本、回滚说明和兼容期。
- **人工最高权限**：编辑的保留、撤下、手动添加、拒绝和锁定决定不得被自动流程覆盖。
- **不重复建设**：优先升级现有 ICE 审核、首页、招聘、移民、财经、SEO 和 APP 接口，不创建同用途的第二套模块。
- **公开性约束**：未发布、审核中、拒绝、删除、私有或来源不足的内容不得进入首页、热榜、Sitemap、Feed 或 APP 公共流。

## 3. 九个中心

### 3.1 内容智能中心

负责采集并形成候选素材，不直接公开发布：

- ICE：ICE 官方、DHS、社交信息、社区信息。
- 中国热点：李老师不是你老师、中文热点来源、突发事件。
- 用户投稿。

每条候选至少记录：来源、原始链接、采集时间、事件时间、地区、证据摘录、附件、可信度和处理状态。

### 3.2 AI审核与事件中心

- 过滤无事实内容、碎片信息和高虚假风险内容。
- 对标题、正文、时间、地点、人物和来源进行新闻去重。
- 多来源描述同一事件时合并为一个事件，并保留全部来源链。
- 升级现有 ICE 审核中心，不另建平行审核程序。
- 证据不足、冲突或高风险内容必须进入人工审核。

### 3.3 内容发布中心

- 快讯：100–300 字，事实明确、来源可追溯。
- 深度新闻：1500 字以上，包含背景、时间线、来源和必要说明。
- 发布前统一分类、公开状态、canonical URL、图片和版权/来源信息。
- 自动化第一阶段只生成草稿，不自行公开发布。

### 3.4 首页推荐中心

#### 今日要闻

- 1500 字以上的已发布深度内容可进入 AI 候选。
- AI 综合字数、新闻价值、时效、来源质量和内容质量作出候选或推荐判断。
- 编辑拥有最高权限：可以保留、撤掉、手动添加或锁定。
- 自动流程不得覆盖编辑锁定和人工排序。

#### 24小时热榜

- 仅允许中国热门头条、美国时政、美国警情、ICE执法动态四个栏目；BIA、移民知识、庇护百科及其他栏目一律不得进入。
- 使用统一热度算法排序，统计窗口为最近 24 小时。
- 超出窗口自动淘汰；人工屏蔽立即生效。
- 同一事件的多篇重复内容不得挤占多个榜位。

### 3.5 移民数据库中心

- 移民法官与法院：法官、法院、批准率、拒绝率。
- 美国判例与新规：BIA、联邦法院、最高法院、USCIS/DHS 政策。
- 移民知识库。
- 数据必须记录来源、统计口径、更新时间和版本，不得混用旧迁移口径与新口径。

### 3.6 招聘商业中心

- 抓取全网公开招聘信息。
- 进入候选的记录必须具有岗位、地点和可核验电话。
- 统一去重、分类和地理推荐。
- 缺少必填项或来源不可核验的记录不得公开。

### 3.7 财经中心

- 股票、基金、行情、财经资讯。
- 行情数据与编辑资讯分开标记来源和更新时间。
- 未接入可靠数据源前不得用占位或过期数据冒充实时行情。

### 3.8 SEO增长中心

统一负责 Google SEO、Sitemap、Schema、内链和页面优化：

- canonical、公开状态、路由、Sitemap、Feed 和 Schema 必须使用同一 URL 规则。
- SEO 构建脚本只允许有一个最终输出链；历史脚本若仍执行，必须确认职责或退役。
- SEO 警告分为阻断项和改进项，阻断项不得静默放行。

### 3.9 APP同步中心

- APP 首页、新闻流、移民、招聘和财经模块读取与网站相同的公共数据源和公开性规则。
- APP 不维护第二套发布状态、分类或推荐算法。
- API 变更须向后兼容，并在移除旧字段前提供兼容期。

### 3.10 当前四类任务发布矩阵

- **SEO自动处理**：旧 WordPress/旧代码损坏链接，以及已发布内容的 meta description、canonical、Schema、内链、Sitemap、News Sitemap 和 Feed，由 SEO Lane 自动审计、修复和验证；代码仍走独立分支、CI、预览和唯一部署链，不进入内容后台逐条审核，也不得自动改写新闻事实。
- **移民法官数据自动发布**：只有可追溯的 EOIR/DOJ 官方数据，或带来源、哈希、统计口径和版本的 EOIR 标准化衍生数据，在完整批次通过硬校验且可保留上一成功版本时，才可自动更新现有正式表和公共 API。异常批次必须熔断，不得展示占位或推测数据。
- **招聘人工发布**：采集与清洗可以自动进行，但岗位只进入现有 `job_listings` 非公开 `draft` 状态；管理员在 `/admin/` 确认岗位、地点、可核验公开电话、时效和风险后，才可改为 `open`。
- **李老师不是你老师与 ICE 人工发布**：采集、事实抽取、翻译、去重和草稿生成可以自动进行；包括 ICE/DHS 官方账号在内的所有来源都必须进入现有后台审核队列，由真实管理员确认后才能发布。AI或官方来源标记只能提高审核优先级，不能代替人工批准。

上述四类任务仍由智能运营总机器人统一调度，不恢复旧的独立定时机器人，不建立第二套数据库、审核状态或发布链。

## 4. 标准数据流

采集候选 → 事实过滤 → 事件去重/合并 → AI 草稿 → 人工审核 → 正式发布 → 首页/热榜 → SEO/Feed → APP 同步。

任何模块不得绕过“人工审核 → 正式发布”直接进入公共发现链，除非以后由编辑明确批准某一低风险来源的自动发布规则。

## 5. 冲突防护

每次总机器人运行必须：

1. 检查 main 最新提交、打开的 PR、CI 和生产构建。
2. 选择一个最高优先级且未被占用的业务中心。
3. 标记本轮共享写入范围；若与其他 PR 重叠，只做审计并报告。
4. 修改前再次读取目标文件和数据库契约。
5. 运行相关测试、站点校验和 SEO/公开性检查。
6. 只创建草稿 PR，列出证据、风险、回滚方式和人工验收步骤。
7. 未通过验证时不得合并或部署。

优先级：生产安全/构建故障 → 数据公开性与迁移冲突 → 审核发布链 → 首页推荐 → 数据库/招聘/财经 → SEO → APP 同步。

## 6. 第一阶段验收标准

- 顶层只运行两个机器人：迁移收口机器人和智能运营总机器人。
- 旧机器人保持暂停。
- 找出所有重复定时任务、重复抓取器、重复写入器和重复构建链。
- 建立“模块 → 数据源 → 写入目标 → 调度入口 → 页面/API”的清单。
- 证明首页、网站公共流、Sitemap、Feed 和 APP 使用一致的公开内容规则。
- 所有新改动经草稿 PR、CI 和人工批准后进入生产。

## 7. 后续放权顺序

只有在连续稳定运行并由负责人确认后，才逐步开放：

1. 自动生成草稿。
2. 自动创建修复 PR。
3. 低风险 PR 自动合并。
4. 白名单来源的自动发布。

自动删除数据、关闭服务、取消域名/数据库/Netlify 服务不属于本机器人的权限。
