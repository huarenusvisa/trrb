# TRRB统一用户与互动底座 V1

## 目标
网站、iOS、Android共用一套Supabase Auth、用户资料、评论、点赞、举报、收藏、阅读历史与通知偏好数据。功能可以分阶段上线，但用户ID、评论ID和互动数据不得分裂成多套。

## 注册默认身份
每个新注册用户由数据库触发器自动创建profile：
- 随机中文昵称，由20个前缀×20个后缀组合生成；冲突时自动重试，极端情况下追加6位随机数字。
- 随机默认头像键 `avatar_001`—`avatar_120`。
- `is_custom_name=false`、`is_custom_avatar=false`。
- 用户后续可以修改昵称或头像；所有历史评论通过user_id关联profile，因此会自动显示最新资料。

普通用户不得依靠前端自报管理员身份。平台后续需对“唐人日报、TRRB、管理员、官方、客服、编辑部”等保留词执行昵称校验。

## 数据表
- `profiles`: 统一公开身份。
- `comments`: 新闻评论与回复，`parent_id`支持层级回复。
- `comment_likes`: 一用户一评论一赞。
- `comment_reports`: 一用户对同一评论最多一个举报。
- `favorites`: 登录后的云端收藏。
- `reading_history`: 登录后的跨设备阅读历史。
- `notification_preferences`: 重大新闻、ICE、移民、法律更新、评论回复通知偏好。
- `user_blocks`: 用户屏蔽关系。
- `moderation_actions`: 后台治理审计记录。

## 游客与登录用户
游客可浏览公开新闻和法律内容，并继续使用App本地收藏/历史。登录后再将本地收藏/历史合并进云端，避免强制注册阻塞阅读。

需要登录的互动：发表评论、回复、点赞、举报、跨设备收藏、跨设备历史、个性化推送。

## 评论治理
第一版数据模型已经支持 `published / pending / hidden / deleted` 状态、举报和moderation审计。上线发表评论API前必须增加：频率限制、保留词/敏感词治理、封禁检查、服务端身份校验。禁止仅靠客户端隐藏按钮实现权限控制。

## 头像资源
数据库只保存稳定的 `avatar_key`。前端统一将 `avatar_001`—`avatar_120` 映射到TRRB自有头像资源。不得依赖第三方随机头像服务作为生产真源。

## 第一阶段验收
- migration存在并可审计；
- 注册触发器生成profile与通知偏好；
- 随机昵称和头像由数据库统一生成；
- 评论、点赞、举报、收藏、历史、通知、屏蔽、治理表齐全；
- 用户数据表启用RLS；
- 网站、iOS、Android后续只允许复用这一套身份主键。
